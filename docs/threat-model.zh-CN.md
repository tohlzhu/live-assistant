# 威胁模型

[English](threat-model.md) | 简体中文

Live Assistant 把浏览器操作变成本机 shell 和 CLI 输入，因此**能登录页面就等于拥有运行用户的 shell 权限**。本文列出当前实现的信任边界、控制措施和已知的残余风险。架构见[架构](architecture.zh-CN.md)。

## 信任边界

| 边界 | 可信方 | 不可信内容 |
|---|---|---|
| 浏览器 ↔ 后端 | 输入正确密码的用户 | 其他本机/网络来源的请求、跨站页面 |
| 后端 ↔ tmux/CLI | 用户直接的键盘操作、用户批准的提案 | 终端输出、CLI 打印的“完成”、屏幕上的提示文字 |
| 后端 ↔ 模型 | 用户的话（经 Live 转写） | 模型输出、助手自己的话、引述内容、终端内容被模型复述的部分 |
| CLI ↔ hook | 后端经 `hook.sock` 返回的决定 | hook 输入中的工具参数（只用于展示） |
| 后端 ↔ Foundry | 本机 Entra 登录 | 未经校验的端点、重定向 |

## 威胁与控制

| 威胁 | 控制措施 | 残余风险 |
|---|---|---|
| 远程或跨站访问 shell | 只监听 `127.0.0.1`；精确 Host 校验；登录 POST 校验 Origin；cookie 为随机 256 位、内存保存、`HttpOnly` + `SameSite=Strict`（HTTPS 时加 `Secure`），8 小时过期；登录有速率限制；CSP `default-src 'self'`，静态资源本地提供 | 本机其他用户或进程若能访问 loopback 并知道密码即可登录；经 SSH 隧道/反向代理暴露时，安全性取决于隧道和代理配置 |
| 密码泄露 | 密码只在后端进程环境中，至少 16 字符，常数时间比较；不传给 session 环境，不写入 `.env`、日志或状态文件 | 进程环境对同用户的其他进程可见 |
| 模型或终端内容冒充授权 | 只有按钮或用户语音中的“批准/拒绝/始终允许 N”能决定提案；助手的话、引述、终端文字和沉默不授权；解释器只产生提案，从不执行；终端内容在模型提示中标为不可信数据 | 语音转写错误可能把用户的话识别成决定；卡片和语音提醒都会给出编号与准确内容，需要用户核对 |
| 提案过期或目标漂移 | 提案绑定 session 与授权纪元；用户接管键盘、等待反馈或进程结束使其失效；屏幕确认在提示离开屏幕时失效；解释期间用户操作过终端会在卡片上标注 | 程序输出不会使提案失效（human-in-loop 的取舍），批准时屏幕内容可能已经变化 |
| 始终允许被滥用 | 只匹配同一 session 中完全相同的 `(kind, key)`（按键提案的 key 是规范化后的整个按键序列）；撤销、等待反馈或进程结束清除；不跨 session | 不计次、不限时：批准后同一操作会持续自动放行，直到用户撤销 |
| 屏幕识别误判 | `[y/N]`、菜单、信任对话框识别只产生 `prompt` 提案，卡片提示核对终端；不推测不明确的选择键 | 纯终端交互没有跨进程原子性，不是强审批协议 |
| hook 通道被冒用或失效 | `hook.sock` 权限 600，位于 700 的状态目录；hook 只接受 allow/deny；socket 不可用、后端退出或选择“在终端处理”时 hook 静默退出，原生提示接管 | 同一用户的其他进程可以连接该 socket；Codex 需要用户在 CLI 内用 `/hooks` 信任 hook |
| CLI 越权 | 不绕过 CLI 原生权限与沙箱：各 CLI 按用户自己的配置无参数启动（只追加 hook 参数），权限与沙箱由该配置决定；起始目录必须位于工作区或 `LIVE_ASSISTANT_ROOTS` 之内（按路径和真实路径两次检查，拒绝 `..` 与符号链接逃逸） | CLI 以运行用户身份执行并复用其全部本机配置与登录；目录限制只约束起始目录，进程本身（尤其是 shell）不受目录限制 |
| 凭据泄露 | Foundry 只用 Entra（`AzureCliCredential`），不使用 API key；token 只在内存中，不写入配置、参数、终端或 Web 响应；助手不为 harness 代理模型请求；启用 `LIVE_ASSISTANT_DSH_FOUNDRY_TOKEN` 时，DSH 的 `FOUNDRY_TOKEN` 只存在于该 session 的进程环境（不进 argv、tmux 全局环境、状态文件或 Web 响应），约 1 小时过期；端点必须是 Foundry HTTPS 根地址，请求禁止重定向 | 本机 `az login` 状态本身是高价值凭据；session 继承后端环境（只去掉 `LIVE_ASSISTANT_PASSWORD`），后端环境里的其他秘密对 harness 及其子进程可见 |
| 敏感内容发送给模型 | 发给 Live 和解释器的终端内容经过 `redact`（私钥、Bearer、常见 token、`password=` 等、UUID、邮箱）和压缩 | 脱敏基于模式匹配，不能识别所有秘密；用户终端保留原始内容 |
| 对话内容落盘 | 用户和助手的转写写入状态目录中的 `live-transcript.jsonl`（文件 600，目录 700），逐段 `redact`，超过 4 MiB 轮转、只留一个旧文件；`events.jsonl` 只记长度、ID 和原因，不记说的话 | 转写片段逐段脱敏，跨片段的秘密可能漏过；能读状态目录的同用户进程可以读到最近的对话 |
| 重复计费或丢失会话 | Live 创建 POST 不重试；结果不确定时记为 `uncertain` 并阻止自动重建；已知 session ID 的会话在重启后通过重新附着关闭 | **没有费用上限**；harness 自身的模型用量不经过助手，不被记录：语音连接保持期间持续计费，界面只显示已知用量，不等于账单 |
| 状态损坏或并发写 | 原子写（fsync + rename）；写失败后阻止后续变更和终端输入；启动时以 abstract socket 锁定状态目录，第二个后端在改动状态前被拒绝 | 同机其他进程可抢先绑定同名 socket，使后端无法启动（只影响可用性） |
| 输入重放 | 后端重启不重投任何输入；已批准未确认送达的提案标为 uncertain；验收不重放 | 用户需要自己判断 uncertain 的操作是否已生效 |
| 文件上传覆盖或越界 | 上传只能写单个文件名（拒绝 `/`、`\`、`..`），先写临时文件再 `link()` 发布，已存在的同名文件不会被覆盖；上传和下载的路径按真实路径检查必须位于工作区或 `LIVE_ASSISTANT_ROOTS` 内；上传校验 Origin，下载依赖 `SameSite=Strict` cookie 并拒绝跨站 `Sec-Fetch-Site`；上传的文件内容不发送给模型 | 根目录检查只是防误操作：页面本身已有 shell 权限，用户仍可在终端里读写任何有权限的文件 |
| 资源耗尽 | 字节级缓冲上限（输入、JSON 请求体、单个上传文件、WebSocket 消息、SDP、上下文、TTS 文本）；慢客户端断开后重新取快照 | 不限制 session 数量、运行时间或提案数量 |

## 不在范围内

- 多用户或多租户访问控制：只有一个共享密码。
- 防御同一操作系统用户下的恶意进程。
- 把端口直接暴露到公网。远程访问应使用已授权的 SSH 隧道，或自行配置 HTTPS 反向代理并设置精确的 `LIVE_ASSISTANT_ORIGIN`。
