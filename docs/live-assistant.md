# Live Assistant: running, recovery and acceptance

English | [简体中文](live-assistant.zh-CN.md)

## Starting

Requires `tmux` 3.4 on the local machine. `npm ci` installs the pinned Node 22.19.0 into `node_modules/.bin/node`, and the npm scripts use it automatically; there is no build step. System services are not modified. claude, codex, copilot and dsh are installed and configured by the user; the assistant only looks them up in PATH and launches them. If dsh is installed under an nvm-managed Node 22, run `nvm use 22` before starting.

```sh
nvm use 22
# Keep the application password in the process environment, not a file or log.
read -rsp 'live assistant password (16+ characters): ' LIVE_ASSISTANT_PASSWORD
export LIVE_ASSISTANT_PASSWORD
npm run assistant
```

By default it listens only on `127.0.0.1:8787`. Open the corresponding loopback URL and sign in with the password above. A login is valid for 8 hours; "Log out" (`登出`) in the avatar menu at the top right invalidates the current login and disconnects every page opened with the same login, while terminal sessions keep running. The same bar shows the server's CPU usage, memory used, and the usage percentage of the disk holding the workspace, updated every 5 seconds; hover to see the load, totals and available amounts, the tmux server PID, and the pane PID of each running session. For remote access, use an authorized SSH loopback tunnel, or configure your own HTTPS proxy and set an exact `LIVE_ASSISTANT_ORIGIN`; do not expose an interface with shell execution rights directly to the internet. The browser captures the microphone in an HTTPS or localhost secure context.

| Setting | Description |
|---|---|
| `LIVE_ASSISTANT_PASSWORD` | Required, at least 16 characters, process environment only; do not put a Foundry token/API key here |
| `LIVE_ASSISTANT_STATE` | Defaults to `.live-assistant`; private state and the tmux socket |
| `LIVE_ASSISTANT_WORKSPACE` | Defaults to `workspace` under that directory; the default session directories `<harness>-work` are created here; always an allowed root |
| `LIVE_ASSISTANT_ROOTS` | Additional roots in which harnesses may be launched (`:`-separated, subdirectories included); must exist at startup |
| `LIVE_ASSISTANT_DSH_PROFILE` | DSH profile, defaults to `dsh-tui` |
| `LIVE_ASSISTANT_DSH_FOUNDRY_TOKEN` | When set to `1`, obtains a temporary Entra token as `FOUNDRY_TOKEN` for each new DSH session |
| `LIVE_ASSISTANT_PORT` | Defaults to 8787; tests use a random port to avoid interfering with existing services |
| `LIVE_ASSISTANT_ORIGIN` | Optional; the exact scheme/host/port of the trusted browser |
| `FOUNDRY_LIVE_ENDPOINT` / `FOUNDRY_TTS_ENDPOINT` / `FOUNDRY_INTENT_ENDPOINT` | HTTPS OpenAI root endpoints of the authorized Foundry resources that host live voice, read-aloud and the intent interpreter respectively; they can be in different regions, see `.env.example`; a model whose endpoint is unset is unavailable |
| `AZURE_SUBSCRIPTION_NAME` | Passed explicitly to AzureCliCredential without switching the shared default subscription; it only determines the token's tenant, so all resources must be in the same tenant and the caller must have been granted an Azure AI role on them |
| `FOUNDRY_LIVE_DEPLOYMENT` | Defaults to `gpt-live-1` |
| `FOUNDRY_LIVE_VOICE` | Defaults to `marin`; the live voice, fixed when the connection is created, takes effect the next time voice is connected |
| `FOUNDRY_TTS_DEPLOYMENT` | Defaults to `gpt-4o-mini-tts`; used to read pending-confirmation reminders aloud (`/api/speech`) |
| `FOUNDRY_TTS_VOICE` | Defaults to `alloy`; the read-aloud voice |
| `FOUNDRY_INTENT_DEPLOYMENT` | Defaults to `gpt-6.1-sol`; only deployment names starting with `gpt-` are accepted |
| `FOUNDRY_INTENT_EFFORT` | Defaults to `low`; reasoning effort of the intent interpreter, one of `none/minimal/low/medium/high/xhigh`; Foundry returns 400 for values the model does not support |
| `LIVE_ASSISTANT_VERIFY_TIMEOUT` | Independent verification timeout in seconds, defaults to 600 |
| `LIVE_ASSISTANT_HOOKS` | When set to `0`, no PermissionRequest hook is injected into Claude/Codex and only screen recognition is used |
| `LIVE_ASSISTANT_CHROMIUM` | Chromium path used by `test:browser` / `test:live`; defaults to the Chromium installed by the current Playwright version |

Except for the password, state directory, port, origin and Chromium path, the environment variables in the table above are defaults that can be overridden under avatar menu → "Settings" (`设置`) and take effect immediately (saved in `<STATE>/settings.json`; see the [README](../README.md#configuration) for details). Disconnect voice before changing the live voice endpoint or the subscription (the read-aloud and intent interpreter endpoints do not require this). The "Preview" (`试听`) button next to a voice reads a sample in the selected voice (the live voice preview is a short GPT-Live session and counts toward usage).

When Foundry is not configured, the terminal remains usable, and voice, read-aloud and model-driven task management are clearly shown as unavailable. Once Foundry is configured and native Entra login is complete, the live model uses `gpt-live-1`, the intent interpreter defaults to `gpt-6.1-sol` (reasoning effort `low`), and read-aloud uses the TTS deployment. No substitute model is silently selected, and no API key is used.

The model each harness uses is determined by the CLI's own configuration; the assistant does not configure model routing: Claude, Codex and Copilot are launched directly with the user's configuration; DSH enters its TUI via `dsh --profile dsh-tui`, and after pressing Esc you select a Foundry model with `/model`. Sessions inherit the shell environment in which the backend was started (minus the login password `LIVE_ASSISTANT_PASSWORD`, the variables injected by `npm run`, and the PATH prefix); the environment is passed through the tmux client environment and never appears in command-line arguments or on disk. When the DSH token switch is on, the token is injected only into that DSH process and expires in about 1 hour; once it has expired, just create a new DSH session.

## Usage: human in the loop

This software is not an unbounded automatic loop: the user decides when to stop. The system sets no limit on the number of executions, number of items, number or lifetime of authorizations, or monthly calls; it only keeps byte-level buffers that prevent the process from crashing.

- **Terminal**: Click "New session ▾" (`新建 session ▾`) and pick a harness in the expanded menu (harnesses that are not installed are labeled "Not found" (`未找到`) and cannot be selected) to create a session; in the dialog, choose the default directory `<workspace>/<harness>-work` or a custom directory inside an allowed root (out-of-bounds paths return 403; symlinks are checked by their real path). Click a tab to switch to it; typing directly operates the native CLI (typing or clicking automatically takes over the keyboard and invalidates that session's still-undecided input/key/terminal-confirmation proposals; mouse movement, the wheel, focus and terminal replies are only forwarded and do not count as taking over. The command-bar button toggles between "Take over keyboard" (`接管键盘`) and "Hand back keyboard" (`交还键盘`); handing back does not restore proposals that were already invalidated, and moves input focus to the "Task / Feedback" (`任务 / 反馈`) input box). Keyboard and mouse, control keys, paste (automatically chunked), resize, and native trust/permission prompts are all handled by the real terminal/CLI. The terminal fills the black area and adapts to the window: when nobody has taken over the keyboard, the page currently viewing it determines the PTY size; when someone has taken over, the page that took over wins. Other sessions keep running, and operations on different sessions do not block each other.
- **Tab markers**: Tabs are uncolored by default; click the small dot to the left of the name to choose one of 8 preset colors (or choose "None" (`无`) to clear it), and the selected tab's bottom border and the terminal border also use that color. Double-click a tab name to add or edit a note (up to 40 characters; Enter saves, Esc cancels, clearing it deletes the note). Colors and notes are saved immediately, persist across reloads, and are given to the assistant as part of the session summary, but do not affect authorization. When the status is running, the tab shows no status word; only other statuses such as terminated are shown. When there are too many tabs they wrap onto more lines, and no horizontal scrollbar appears.
- **Files**: "Upload file" (`上传文件`) saves the selected files one by one to the current session's current working path (tmux `pane_current_path`, which follows `cd` in the shell); a name clash is an error and nothing is overwritten; the size limit is `LIVE_ASSISTANT_UPLOAD_MB` (default 2048); when done, the voice assistant is silently told the path and size. "Download file" (`下载文件`) downloads a single regular file by a path relative to the current working path (or an absolute path). Both require the path to be inside an allowed root.
- **Numbered proposals**: Input typed on your behalf by the assistant, key presses, creating/terminating sessions, recognized terminal confirmations (`[y/N]`, Codex/Claude menus, trust dialogs) and native permission requests are all shown as numbered "N." cards (numbers cycle through 1–99, skipping numbers that are still pending or approved and still executing; voice reads them as plain numbers, e.g. "3 号" (number 3)). Several can exist at the same time and can be decided in any order. Buttons: "Approve" (`批准`) / "Reject" (`拒绝`) / "Always allow" (`始终允许`) / "Handle in terminal" (`在终端处理`, native permission requests only). When a card notes "you operated this terminal during interpretation" (`解析期间你操作过该终端`), check it again.
- **Do not disturb the focused terminal**: When the page's input focus is in a session's terminal (and that browser window is in the foreground), the terminal confirmations and native permission requests produced by that session are only hidden: no card pops up, nothing is read aloud, and the voice assistant is told not to remind you (the hook keeps waiting). Clicking a tab name puts keyboard focus into that session's terminal, which triggers hiding just like clicking "Handle in terminal" (`在终端处理`). When focus leaves, items that are still waiting pop up again under their **original numbers** with a reminder; no new card is created. Only typing in that terminal (or clicking "Handle in terminal") actually ends the card: the hook gives up, the native prompt takes over, and a native menu that appears afterwards is not recognized as a new card until you press Enter. Proposals you initiate, such as assistant input on your behalf or creating/closing sessions, are not affected.
- **Always allow**: Keeps automatically allowing exactly identical prompts, inputs or key sequences in the same session, with no count or time limit; the "Revoke" (`撤销`) button, "等待反馈" (wait for feedback), process exit or termination clears it. Old authorizations do not carry across sessions.
- **Native permission hook**: Claude Code gets a local hook injected via `--settings`, and Codex via `-c hooks.PermissionRequest=...`. The hook hands the request to you for a decision via `hook.sock` (mode 600); when you choose "Handle in terminal" (`在终端处理`) or the web backend is unavailable, the hook outputs nothing and the native prompt appears as usual; after you click "Handle in terminal", the page switches to that session and puts keyboard focus into the terminal, so you can act directly in the native prompt; when you answer the native prompt directly in the terminal, the corresponding card ends with your first key press. Codex requires non-managed hooks to be trusted once inside the CLI with `/hooks`.
- **Voice**: Once connected, you can ask to create a session, append/modify/continue, press keys, query status, or cancel. For key presses you must say the key names, for example "给 vim 按 Esc，再输入 :wq 回车" (press Esc in vim, then type :wq and Enter), "按 Ctrl+C" (press Ctrl+C), "按三次下箭头" (press the Down arrow three times), "按 Shift+Tab" (press Shift+Tab): the card title is "Keys" (`按键`), the content lists each step (`Escape → ":wq" → Enter`), and after approval the steps are sent in order. Supported: visible characters, Enter/Esc/Tab/Space/Backspace, arrow keys, Home/End, PageUp/PageDown, Insert/Delete, F1–F12, and Ctrl/Alt/Shift combinations. If you only describe the effect ("退出 vim" (quit vim), "中断它" (interrupt it)), the assistant asks which keys to press. Combinations the terminal cannot distinguish (Ctrl+Enter, Shift+Enter, Shift+Esc, Ctrl+Tab, Ctrl+Backspace, Ctrl+Shift+letter, Shift+non-letter) are explained and rejected, never sent as a different key. Decide with "批准 N / 拒绝 N / 始终允许 N" (approve N / reject N / always allow N) (Chinese numerals are supported, and whole sentences such as "好的，批准 3 号提案吧" (OK, approve proposal number 3), "拒绝提案 12" (reject proposal 12) and "不同意 5 号" (disagree with number 5) are also accepted; cards hidden because focus is in the terminal can also be decided by number); when only one card is pending, the number can be omitted. The whole sentence must consist only of pleasantries, decision words, the number, and words such as "提案/号/吧" (proposal / number / the particle 吧): negation ("不批准 3 号" (do not approve number 3)), questions ("批准 3 号吗" (approve number 3?)), quotes ("他说批准" (he said approve)), several items in one sentence, and decision words embedded in a long sentence do not count as authorization, and neither do the assistant's own words or silence; when a decision is not recognized, the voice assistant asks you to say it again in the form "批准 N" (approve N). "等待用户意见/等待反馈/暂停当前会话" (wait for user input / wait for feedback / pause the current session) immediately clears always allow for the focused session and invalidates its pending proposals, without freezing the process. "切到某 session" (switch to a given session) switches the page directly (it sends no content and needs no approval); when sending or creating, ask it to "切过去" (switch over) and the page follows (a newly created session is switched to after its launch is approved); "关闭某 tab" (close a given tab) produces a "Close tab" (`关闭 tab`) card, and approving it terminates the process and closes the tab.
- **Copy and paste**: The CLI's mouse tracking is left as is (TUIs other than the shell receive clicks and drags, so dragging directly cannot select text). To copy, click "Select to copy" (`选择复制`) in the command bar (it highlights): the next press-drag-release selects text only in the page, and on release the selection is written to the clipboard with a notice showing the line and character counts, after which the button resets; in the meantime mouse events are not sent to the harness, and Esc cancels. "Copy screen" (`复制屏幕`) copies the text of the current session's visible screen (soft-wrapped lines are joined back into one line) and shows a success notice. To paste, use "Paste" in the browser's context menu; Ctrl+V is still sent to the CLI as `^V`, and Ctrl+C is still interrupt; neither is used for the clipboard.
- **Hand off to the assistant**: The text in the input box, together with the list of running sessions (name, note, harness) and the session on the current page, is handed to the interpreter; if no session is named, it goes to the session on the current page. Distinguish sessions with the same name (for example two shells) with notes. When the target or content cannot be determined, no card is created, and the error bar shows "Clarification required: …" explaining what is missing.
- **Order of cards and errors**: Cards are at the top of the right column, and errors are below them and do not float; errors hide automatically once the backend error clears. When a voice decision refers to a number that is no longer pending, the assistant reports that number's status and reason (for example "the user took over the terminal") and answers that delegation; it likewise answers the delegation when interpretation fails, a voice decision did not take effect, or the client has already handled the same utterance directly, so the voice model never waits indefinitely.
- **Read-aloud reminders**: With "Read pending confirmations aloud" (`朗读待确认提醒`) checked, newly appearing cards have their number and a summary of their content read aloud by TTS (the preference is saved in this browser).
- **Conversation text**: The right column shows turns in speaking order as "You:" / "Assistant:" (`你：` / `助手：`); a new turn starts after something is handed to the assistant (delegation) or after a pause of more than 1.5 seconds, and when a transcription has no usable timestamp a new turn also starts after the assistant replies; when scrolled to the bottom it follows new speech, and scrolling up to read back is not interrupted.
- **Context compression**: Terminal content sent to Live and the interpreter first has spinners, timers and borders removed and is deduplicated, and each session sends only new lines; the session catalog only sends sessions that changed; very long transcripts fold older content instead of erroring or refusing. The user's terminal itself keeps the raw output.

The status pill next to the "Voice assistant" (`语音助手`) title shows the connection state ("Not connected" (`未连接`), "Connecting…" (`连接中…`), "Connected" (`已连接`), "Connection degraded" (`连接受损`), "Connection failed" (`连接失败`), "Disconnecting…" (`正在断开…`); the failure reason is shown below the control). "Connect voice / Disconnect voice" (`连接语音 / 断开语音`) is a single button that becomes a red-outlined "Disconnect voice" (`断开语音`) once connected; "Microphone on/off" (`麦克风 开/关`) and "Assistant voice on/off" (`助手声音 开/关`) are toggles whose text and highlight always show the current state, and they are unavailable when not connected. Turning off the assistant voice only stops playback (reminders become silent context); turning off the microphone only stops capture; disconnecting voice only closes the Provider session, and after reconnecting both toggles return to "On" (`开`). Closing or refreshing the page and shutting down the web backend do not terminate terminals. Only explicit termination, closing a tab, or approving a cancel proposal ends a given session: the × on a tab terminates the process and closes the tab (without further confirmation; if termination is not confirmed, the tab stays and an error is shown); "Terminate process" (`终止进程`) at the top ends the process but keeps the tab.

### Managed runs and independent verification

Once authorized, append, modify and continue produce a new managed run, and the old run is marked `superseded` rather than being passed off as cancelled; key presses only operate the current task and do not create a new run. Native terminal output carries only processRunId, observationId and an increasing sequence; mixed CLI output is not guessed to be a completion event of any task.

"Independent verification" (`独立验收`) only runs local commands that the user explicitly provided and confirmed, bound to a runId; the result is passed/failed/unknown/stale. The timeout is configurable (default 10 minutes); the command runs in a separate process and does not appear in the terminal; the tail of the output is kept (up to 16000 characters) and can be viewed by expanding "Verification output (tail)" (`验收输出（尾部）`) below the status line, and while it is running you can click "Cancel verification" (`取消验收`). New input marks a late result as stale; a duplicate operation ID is not rerun; after a restart, unconfirmed verifications are marked unknown and are not replayed. `passed` only proves that this particular command run passed.

## Recovery and resources

A new session's initial task is delivered only after the startup output has stabilized; if you take over the keyboard before delivery, the task is abandoned. When the web backend exits, it closes the Live session and the observers and keeps the tmux sessions; starting again with the same state directory re-observes the original processes, proposals that were approved but not confirmed as delivered are marked uncertain, pending proposals are invalidated, and no input is re-sent. After a tmux/VM restart, processes that no longer exist are marked lost.

State is saved in `sessions.json` (v2, migrated automatically from v1; only recently decided proposals/operations are kept as the working set), the full history is appended to `events.jsonl`, Live transcripts and delegation boundaries are redacted and appended to `live-transcript.jsonl` (local only, rotated above 4 MiB), Live session records and monthly usage are in `live.json`, and interpreter usage is in `interpreter-usage.json`. Closed tabs are marked `closed` in `sessions.json` and no longer appear in the UI or the Live session catalog. See [Architecture](architecture.md#state-and-recovery) for a description of each file.

Terminate or close sessions you no longer need one by one through the UI; just closing the web process does not clean them up. The tmux server exits together with the web backend when there are no sessions; a global `tmux kill-server` or bulk kill by process name is never used.

## Verification commands

```sh
npm test               # unit and integration tests, no model calls
npm run test:browser   # headless Chromium against a temporary backend

# Paid: real gpt-live-1 session in an isolated state directory under .live-assistant/.
npm run test:live
npm run test:live -- --mandarin
# Reuse previously accepted Mandarin audio; the new Live workflow still runs for real.
npm run test:live -- --mandarin --mandarin-fixtures .live-assistant/<accepted-voice-evidence>
```

`test:browser` and `test:live` launch the Chromium installed by the current Playwright version by default; you can also point `LIVE_ASSISTANT_CHROMIUM` at an existing Chromium. The Chromium sandbox is kept. `test:live` requires `FOUNDRY_LIVE_ENDPOINT`, `FOUNDRY_INTENT_ENDPOINT`, `az login` and a local `espeak-ng`; missing tools cause an error, and audio tests are never skipped and reported as passed. Mandarin mode uses a separate GPT-Live session to generate single-sentence audio and must check the complete transcript and the close receipt; generating a repeated utterance counts as a failure. You can also explicitly reuse existing audio that has success evidence and a matching transcript, without fabricating a new generation record. The script uses a separate state directory on every run, writes the results to `result.json` inside it, and on exit cleans up each newly created terminal one by one and confirms that Live is closed.

The launch, reasoning and hook behavior of the real Claude Code / Codex / Copilot / DSH have no automated scripts; accept them using the README's ["Manual testing with real harnesses"](../README.md#manual-testing-with-real-harnesses) and the manual test checklist below.

## Manual test checklist

1. `npm ci` (Node 22.19+ or 24+), `nvm use 22`, set `LIVE_ASSISTANT_PASSWORD`, the three `FOUNDRY_*_ENDPOINT` variables and `AZURE_SUBSCRIPTION_NAME`; after `az login`, run `npm run assistant` and open `http://127.0.0.1:8787` through an SSH tunnel.
2. Create a Codex session and first run `/hooks` inside the CLI to trust the live hook. Put focus in the "Task / Feedback" (`任务 / 反馈`) input box first, then have it run a command that needs approval; confirm that an "N. Tool permission" (`N. 工具权限`) card appears, and try "Approve / Reject / Handle in terminal / Always allow" (`批准/拒绝/在终端处理/始终允许`) in turn. Then have it request several commands in a row; after a card appears, choose directly in the terminal's native menu and press Enter, and confirm that each card closes after your key press and the voice assistant no longer reminds you. Then leave focus in the terminal and trigger one more, and confirm that no card appears and the native menu works as usual (whether the native menu is shown while the hook is waiting depends on the CLI and must be confirmed here); without answering, switch to another tab or click the "Task / Feedback" input box, and confirm that the card that pops up has the original number and includes "Handle in terminal" (`在终端处理`).
3. Create a Claude Code session and repeat step 2 (no `/hooks` needed). Create a Copilot session and confirm that its native permission menu is recognized as a "Terminal confirmation" (`终端确认`) card. Create a DSH session, press Esc, select a Foundry model with `/model`, and complete one conversation.
4. Approve a card while a spinner keeps spinning, and confirm that it does not become invalid because the output changes; open two cards at the same time and decide them in reverse order.
5. Check "Read pending confirmations aloud" (`朗读待确认提醒`) and confirm that new cards are read aloud; connect voice and confirm that the status pill shows "Connecting…" (`连接中…`) and then "Connected" (`已连接`), that the button changes to "Disconnect voice" (`断开语音`), and that toggling "Microphone" (`麦克风`) and "Assistant voice" (`助手声音`) switches the text between on and off (`开`/`关`); say "批准 1 / 拒绝 2 / 等待反馈" (approve 1 / reject 2 / wait for feedback) and confirm that the effects match the cards; then say "切到另一个 session" (switch to another session) and "关闭它的 tab" (close its tab), and confirm that the page switches and that the tab closes after the card is approved.
6. In a mouse-tracking TUI such as claude/copilot, click "Select to copy" (`选择复制`) and drag to select some text, then after releasing paste it elsewhere to check it; then click "Copy screen" (`复制屏幕`) and check the full-screen text.
7. Paste 6000 Chinese characters into the shell (for example after `cat > paste.txt`), and confirm that the connection does not drop and the content is complete.
8. After a long conversation (multiple sessions, long output), ask for status and observe whether the assistant still grasps the key points.

## Evidence and acceptance boundaries

For the scope of the automated tests, see the README's ["Testing"](../README.md#testing). Real human Mandarin speech and actual microphones/speakers, long-duration/noisy/echo conditions, and the end-to-end behavior of hooks in real CLIs require manual testing; a pure terminal has no strong cross-process approval atomicity and no general pause capability, so no claim of production readiness is made on this basis. The known Live/model/CLI usage is not the same as a complete dollar bill.
